**Tech Stack:** Rust workspace, SQLite, FTS5/optional embeddings, MCP stdio, CLI, Altevra resident modes, Codex OAuth/OpenAI-compatible model router, skill adapters for Claude/Codex/Cursor/Antigravity/Hermes.

# P1 — Finish real skill factory vertical slice

## P1.1 Add explicit `SkillCandidate` metadata instead of stuffing summary strings

**Objective:** Stop using only `summary` text for machine fields like tool_calls/file_changes/renderer.

**Files:**
- `crates/altevra-db/src/repositories/improvement_signals.rs`
- migrations if needed
- tests in `altevra-db`

**Design:** Add JSON metadata to improvement signals or encode typed fields in a new table/view:

```json
{
  "tool": "hermes",
  "project": "altevra",
  "turns": 6,
  "tool_calls": 4,
  "file_changes": 0,
  "renderer": "codex_gpt",
  "raw_trace_ref": "session:<id>"
}
```

**Acceptance:** no code has to parse prose summary to route/render candidates.

## P1.2 Include turn/file refs, not only session refs

**Objective:** Give Codex/GPT precise raw evidence to replay.

**Files:**
- `crates/altevra-cli/src/commands/import.rs`
- `crates/altevra-db/src/repositories/improvement_signals.rs`
- maybe `sessions` repository helpers

**Steps:**
1. During import, collect relevant `turn:<id>` refs for tool calls/results.
2. If file changes exist, include `file_change:<id>` refs.
3. Persist them in proposal `evidence_refs`.

**Acceptance:** promoted skill proposal evidence contains `session:*` plus precise turn/file refs where available.

## P1.3 Build renderer handoff command

**Objective:** Create an explicit CLI path that stages a skill draft from a triaged skill proposal.

**Command shape:**

```bash
altevra skill-factory render --proposal <id> --dry-run --json
altevra skill-factory render --proposal <id> --out docs/generated/skills/<slug>/SKILL.md --json
```

**Rules:**
- Must replay raw refs before model prompt.
- Must dedupe against existing skills.
- Must validate SKILL.md frontmatter and required sections.
- Must safety-scan for secrets/PII.
- Must default dry-run.
- Must not install into external tools without separate approval/apply path.

**Acceptance:** test proves renderer refuses proposal with missing raw refs; dry-run produces deterministic staged draft with noop provider/stub.

## P1.4 Add Codex/GPT renderer provider integration test with stub

**Objective:** Codify the doctrine without needing live ChatGPT credits.

**Files:**
- `crates/altevra-llm` or new `crates/altevra-brain/src/skill_factory.rs`
- tests

**Acceptance:** stub renderer receives raw replay packet and returns a valid SKILL.md draft; validator passes; no external write occurs.

## P1.5 Add MCP visibility, not MCP apply

**Objective:** Agents can see candidates/proposals but cannot apply them.

**MCP tools:**
- `list_skill_candidates`
- `get_skill_proposal`
- maybe `request_skill_render` as proposal-only if HP-1 remains safe

**Never expose:** approve/apply/install/grant.

**Acceptance:** HP-1 forbidden-tool-name test still passes.
