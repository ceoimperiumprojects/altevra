## 1. Security / Privacy Breaker Review

> Codex execution attempted twice (visible Herdr pane + foreground `codex exec`) and failed with: `ERROR: Your workspace is out of credits. Ask your workspace owner to refill in order to continue.`
> Hermes performed fallback skeptical review so the architecture round can proceed. Re-run the same prompt after Codex credits are refilled.

### 1. Critical blockers

1. **Exposure gate must be the only context boundary.** Sections §2 and §3 agree conceptually, but implementation must expose one shared `exposure_gate(object_id, caller, purpose, max_sensitivity, domain_scope)` API. If each tool/retriever implements its own filter, personal/business leakage is inevitable.
2. **Raw secret ingress must fail before persistence.** §2 says redaction-before-persist, while §1 permits broad payload objects. P0 must define a single pre-write scanner and quarantine lane; otherwise secrets can become durable before safety policy runs.
3. **Delete/forget + packet audit conflict needs explicit policy.** §2 deletion/RTBF and §3 packet audit trail can conflict. Final contract must state whether audit entries retain tombstoned refs only, redacted summaries, or encrypted sealed evidence.

### 2. High risks

- Prompt/self-improvement agents in §4 can ingest failed packets/logs; they must treat all observed text as untrusted data and never as instructions.
- Tool registry in §5 can accidentally normalize tools that print secrets; tool outputs need sensitivity labels and redaction wrappers.
- Domain defaults in §6 must be applied at object creation, not later cleanup.

### 3. Medium risks

- Cloud sync language appears in several sections; final contract needs one sync ceiling matrix.
- Obsidian human edits can bypass DB constraints unless import/reconcile runs through the same safety gate.

### 4. Required contract changes

- Add one canonical `ExposureGate` contract.
- Add one canonical `PreWriteSafetyGate` contract.
- Add explicit RTBF/audit retention rule.
- Add tool-output sensitivity contract.

### 5. Missing acceptance tests/evals

- Secret-looking input fixture must never persist raw payload.
- Relationship/health/legal/financial object must never appear in general project packet.
- Deleted object must not appear in retrieval; audit shows only tombstone/redacted ref.
- Prompt injection in captured browser/page text must not alter resident-agent prompt.

### 6. Good parts that should stay

- Capture != exposure is the right core law.
- Pre-rank exposure gate in §3 is correct.
- Review-gated protected changes in §2/§4 are necessary.

### 7. Final recommendation

**Accept with changes**: strong architecture, but P0 must implement shared safety gates before any broad capture.

## 2. Consistency / Drift Breaker Review

> Codex blocked by out-of-credits. Hermes fallback review recorded below; re-run Codex later with `round3-codex-consistency-breaker.md`.

### 1. Critical blockers

1. **Storage engine contradiction must be ratified.** V5 references Postgres/pgvector, while repo/P0/AGENTS point to SQLite-first. Final synthesis must state: P0 is SQLite/local-first; external/vector/cloud backends are adapters, not P0 source of truth.
2. **Status enums are overlapping.** §1 object lifecycle, §2 quarantine/review, §4 proposal status, §5 capability state, and §6 lifecycle retention use related but different statuses. Need a core status family + domain-specific substatus rule.
3. **Markdown vs DB source-of-truth must be per object type.** §3/§5/§6 must not invent separate canonicality rules.

### 2. High risks

- `domain` enum co-owned by §1 and §6 can drift if not generated from one registry.
- Capability/tool status in §5 overlaps with object `status`; tests must validate allowed combinations.
- Context packets may cache old object revisions unless §3 version pinning is mandatory everywhere.

### 3. Medium risks

- Obsidian folder zones need exact names before implementation.
- Cross-section requests are numerous; without a resolver table, implementation will cherry-pick.

### 4. Required contract changes

- Ratify SQLite/local-first P0.
- Introduce canonical `ObjectStatus`, `ReviewStatus`, `LifecycleState`, `CapabilityState` separation.
- Generate domain registry from one DB table/contract.
- Add contract test that all sections reference the same source-of-truth policy.

### 5. Missing acceptance tests/evals

- Markdown edit reconciliation test: human edits a DB-canonical generated mirror; system creates review item, not direct overwrite.
- Superseded object excluded from context packet unless explicitly requested.
- Capability status transition rejects illegal `current -> installed_without_probe` style jumps.

### 6. Good parts that should stay

- Section ownership and envelope model are solid.
- Cross-section requests are explicit enough to synthesize.

### 7. Final recommendation

**Accept with changes**: consolidate enum/source-of-truth contracts before coding.

## 3. Product / UX / Clutter Breaker Review

> Codex blocked by out-of-credits. Hermes fallback review recorded below; re-run Codex later with `round3-codex-product-breaker.md`.

### 1. Critical blockers

1. **Architecture can become clutter OS if default capture is too visible.** The product must default to curated dashboard/context packets, not dumping every object into Obsidian.
2. **Daily win must be defined.** Pavle needs “what matters today / what changed / what is next,” not a schema museum.
3. **Personal/business boundaries must be effortless.** If Pavle must manually label everything, system fails.

### 2. High risks

- Too many object types can overwhelm CLI/UX; P0 should expose few verbs over many schemas.
- Review queues can become a second inbox; needs priority, batching, auto-dismiss for low-risk noise.
- Skills/tools sharing can distract from ReVesta/GTM unless dashboards preserve priority order.

### 3. Medium risks

- Obsidian zones must hide generated noise by default.
- Self-improvement proposals need “why now” and “impact” fields, not just technical diffs.

### 4. Required contract changes

- Add `daily_brief` / `focus_packet` as first-class product output.
- Add visibility tier: `hidden_generated`, `review_queue`, `dashboard`, `canonical_wiki`.
- Add review queue SLA/priority rules.

### 5. Missing acceptance tests/evals

- Given 100 captured events, dashboard shows ≤10 items and preserves active priority.
- Generated wiki does not create top-level Obsidian clutter.
- Low-confidence repeated noise gets summarized/stale, not surfaced forever.

### 6. Good parts that should stay

- Anti-clutter appears in §6; needs synthesis into product law.
- Context packets can be the UX primitive, not just agent plumbing.

### 7. Final recommendation

**Accept with changes**: force P0 around a daily/focus loop, not broad capture UI.

## 4. Implementation / P0 Sequencing Breaker Review

> Codex blocked by out-of-credits. Hermes fallback review recorded below; re-run Codex later with `round3-codex-implementation-breaker.md`.

### 1. Critical blockers

1. **P0 must not implement every object type.** Architecture is broad; first build one vertical loop with minimal durable objects.
2. **Contracts must become tests before features.** If P0 starts with UI/dashboard/research/connectors, it violates AGENTS.md and repeats current risk.
3. **Vector/embedding backend must be deferred.** BM25/structured filters + exact refs are enough for first vertical context packet.

### 2. High risks

- Self-improvement loop is powerful but should start as proposal-only over small fixtures.
- Skill/tool registry can start as read-only inventory, not auto-install/update.
- Cloud sync can start as metadata policy + export, not sync daemon.

### 3. Medium risks

- Need migration names before schema work.
- Need fixture vault with synthetic personal/business data; no real secrets.

### 4. Required contract changes

- Define P0.0 artifacts: schemas, state machines, fixtures, validation scripts.
- Define P0.1 vertical loop: capture → safety gate → persist object → render Obsidian mirror → compile context packet → audit packet → propose review item.
- Ban dashboard/connectors/cloud sync from P0.1.

### 5. Missing acceptance tests/evals

- One synthetic project decision captured and appears in focus packet with provenance.
- One secret-looking note is quarantined and excluded.
- One human correction supersedes old object and packet excludes old revision.
- One self-improvement proposal is created but not applied.

### 6. Good parts that should stay

- Rust/SQLite/MCP/local-first is implementable.
- Section contracts are specific enough for test-driven P0.

### 7. Final recommendation

**Accept with changes**: cut implementation to one vertical loop + tests first.

## 5. Hermes Resolution

### Accepted blocker resolutions

1. **SQLite/local-first P0 is ratified.** Postgres/pgvector references in V5 are future adapter/cloud-backend notes, not P0 truth.
2. **Shared gates are mandatory before broad capture.** P0.0 must define `PreWriteSafetyGate` and `ExposureGate`; P0.1 must use them in every write/read/context path.
3. **Status families are separated.** Core object lifecycle, review workflow, retention lifecycle, and capability health are separate enums linked by invariants, not one overloaded status.
4. **Context packet is the primary UX primitive.** Altevra should surface focus/daily packets and review queues, not raw capture dumps.
5. **One vertical loop before platform expansion.** P0.1 scope is capture → safety → persist → Obsidian mirror → context packet → audit → review proposal.
6. **Self-improvement is proposal-only in P0.** No silent prompt/schema/skill/policy rewrites.
7. **Cloud sync is policy-only in P0.** No sync daemon until local contracts pass.

### Rejected / deferred

- Full vector retrieval: deferred until BM25/structured/context packet evals are green.
- Dashboard/UI build: deferred; CLI + Obsidian face first.
- Auto-install/update of tools/skills: deferred; read-only registry + proposal path first.

### Codex status

Codex skeptical review was attempted and blocked by account credits. Hermes fallback review is sufficient to proceed with local synthesis, but true Codex breaker pass should be rerun after credits are available.
